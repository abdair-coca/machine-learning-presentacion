01 — Introducción

¿Qué es Machine Learning?|

Contexto del proyecto y conceptos fundamentales antes de ver el código.

¿Por qué existe el Machine Learning?

La programación clásica funciona así: tú escribes reglas explícitas y la computadora las sigue. Pero hay problemas donde las reglas son demasiado complejas o desconocidas — como predecir el precio de una casa. Machine Learning le da la vuelta a eso: en vez de escribir las reglas, le damos ejemplos y el algoritmo aprende las reglas solo.

Si no entiendes nada todavía, no te preocupes — al final de esta presentación todo va a tener sentido.

En este proyecto usamos uno de los algoritmos más simples y poderosos: regresión lineal. Le damos 546 casas con 13 características y sus precios, y el modelo aprende la relación matemática entre ellos.

Programación clásica

  • Tú escribes las reglas
  • Los datos entran, las respuestas salen
  • Las reglas son explícitas y fijas
  • Funciona bien para problemas con lógica clara

Machine Learning

  • Los datos + las respuestas entran
  • El algoritmo aprende las reglas
  • Las reglas son patrones estadísticos
  • Funciona bien para patrones complejos

Conceptos que vas a necesitar

📦
Dataset
La colección de ejemplos con la que entrenamos el modelo. En este proyecto: 546 casas con 13 características cada una.
🔢
Feature (variable X)
La información de entrada que usamos para predecir. En nuestro modelo: el tamaño del lote (lotsize).
🏷️
Etiqueta (variable y)
Lo que queremos predecir. En nuestro modelo: el precio de la casa (price).
📈
Regresión lineal
Encuentra la línea recta que mejor describe la relación entre X e y. La ecuación es: precio = a × lotsize + b.

Antes de entrenar cualquier modelo, siempre visualizamos los datos. El scatter plot nos dice si existe una relación entre lotsize y price. BLOQUE 4 Dividir datos y entrenar el modelo
train_test_split divide el dataset: el 80% para entrenar (X_train, y_train) y el 20% para evaluar (X_test, y_test). El parámetro random_state=42 fija la semilla aleatoria para que la división sea siempre la misma. model.fit() es donde ocurre el aprendizaje: el modelo encuentra la recta que mejor se ajusta a los 436 puntos de entrenamiento. Requiere haber ejecutado los Bloques 1 y 2 primero.
Presiona Ejecutar para ver el resultado.
BLOQUE 5 Evaluar el modelo — MSE y R²
model.predict() usa la recta aprendida para estimar el precio de las 110 casas de prueba. Luego calculamos dos métricas: MSE (Error Cuadrático Medio) mide cuánto se equivoca el modelo en promedio, en dólares al cuadrado. R² mide qué proporción de la variación del precio explica el modelo: 1.0 sería perfecto, 0.0 sería inútil. Requiere haber ejecutado los Bloques 1, 2 y 4 primero.
Presiona Ejecutar para ver el resultado.
BLOQUE 6 Coeficientes del modelo
model.coef_ contiene los coeficientes de la recta aprendida, que indican cómo cambia el precio con respecto a cada característica. model.intercept_ es el término independiente. Requiere haber ejecutado los Bloques 1, 2 y 4 primero.

Limitaciones del modelo

  • Solo usa lotsize como predictor. El precio también depende de bedrooms, baños, ubicación, etc.
  • La regresión lineal asume una relación lineal. Si la relación real es curvilínea, el modelo falla.
  • Los valores extremos (outliers) distorsionan la recta. El dataset tiene casas de $25,000 y $190,000.
  • El modelo no puede extrapolar bien: predecir precios para lotsize fuera del rango observado es poco confiable.

Conclusiones del modelo

¿Qué aprendimos sobre el dataset?

El dataset Housing contiene 546 casas con 13 variables. Al explorar los datos en la Sección 2, observamos que el precio varía entre $25,000 y $190,000 con un promedio de $68,000. La variable lotsize tiene una relación positiva con el precio, pero con alta dispersión — lo que anticipaba que un modelo de una sola variable tendría limitaciones.

¿Qué aprendimos sobre la regresión lineal?

La regresión lineal simple encontró una relación entre el tamaño del lote y el precio de la casa. Sin embargo, el R² obtenido con lotsize como único predictor indica que el tamaño del lote solo explica una fracción de la variación del precio. Variables como el número de habitaciones, baños, acceso a calefacción a gas (gashw) o la zona preferida (prefarea) tienen un impacto que este modelo no captura.

Esto no significa que el modelo sea inútil — significa que es un punto de partida. En un proyecto real, el siguiente paso sería incluir más variables (regresión múltiple) o probar modelos más complejos como Random Forest o Gradient Boosting.

¿Qué aprendimos sobre Machine Learning en general?

El proceso que seguimos en esta app — explorar datos, visualizar, dividir en train/test, entrenar, evaluar — es el mismo proceso que se usa en proyectos reales de ML, sin importar la complejidad del modelo. Lo que cambia con modelos más avanzados es la función de entrenamiento, no el flujo.

Reflexión sobre la herramienta

Construir esta app implicó resolver un problema real: ¿cómo ejecutar Python científico en el browser sin un servidor? La respuesta fue Pyodide — Python compilado a WebAssembly. Esto permitió que la app funcione como un archivo HTML estático, sin necesidad de un servidor. Sin embargo, la complejidad y el despliegue en Vercel hacen que esta Aplicación Web sea util para entender e inspirar a que se pueda crear mas contenido educativo como este.

El resultado es una herramienta que cualquier persona puede abrir, modificar el código del modelo, ver cómo cambian las métricas, y leer una interpretación automática — todo sin instalar Python, sin configurar entornos, y sin conocimientos previos de programación.
